# Android update delivery

Android updates are independent of desktop Beta/Development manifests.

| Android channel | Version stages | Manifest |
| --- | --- | --- |
| Alpha | `alpha`, experimental `dev` | `android-alpha/latest.json` |
| Beta | `beta`, `rc` | `android-beta/latest.json` |
| Stable | no prerelease suffix | `android-stable/latest.json` |

Manifest paths are GitHub release download paths in `sanleesam/DropFlow`.
An unpopulated channel shows "No release published yet", not "up to date".
Changing the channel clears any checked/downloaded candidate. An update requires
both a newer full Semantic Version and a higher Android versionCode; channel
switching never forces a downgrade.

## Trust and installation

- Only HTTPS GitHub release URLs for this repository are accepted. Redirects
  are limited to GitHub's known asset hosts; HTTP downgrade/user-info redirects
  and arbitrary download origins are rejected.
- Manifest size is capped at 64 KiB; APKs at 256 MiB. Exact advertised length and
  SHA-256 must match. The package ID, versionName, versionCode and signing
  certificates must match the candidate and installed app before installation.
- Downloads use app-private cache paths; cancellation removes partial output.
  Each operation has a unique file name so cancelled work cannot delete a newer
  operation's files. No received-file folders or user files are used.
- A non-exported FileProvider exposes only the update cache and grants temporary
  read access to the verified APK. Bytes/identity are checked again at handoff.
- Android performs final signature/upgrade validation and asks the user to
  confirm installation. If "install unknown apps" access is unavailable, the
  app explains it and offers a user-operated settings link. No permission is
  enabled automatically. Debug and release signers are deliberately incompatible.

Checks are manual and contact GitHub only when requested. Download progress is
kept across screen navigation/Activity recreation, not process death. Downloads
restart rather than resume after interruption. Signing-key rotation is not
implemented; the current release identity must remain the same.

## Publication

`android-v<version>` must match the Gradle target. The workflow runs version,
unit and lint gates, builds the signed APK, verifies its original certificate and
embedded version, then generates `latest.json` with size and SHA-256. Both assets
are attached to the versioned release. Only then is that manifest uploaded to
the matching floating Android channel. Channel publication is serialized and
rejects stale install/version ordering. It never writes desktop `latest.json`.

The manifest schema is defined in `AndroidUpdateManifest` and generated by
`scripts/android-updater-manifest.mjs`. `release-baseline.json` records the last
public upgrade baseline; update it only after a successful published Android
release, then choose a newer source target for the next release.

This implementation has unit, emulator UI and APK-preflight coverage. A real
published same-key download/install upgrade remains a release gate; see
[ANDROID_ALPHA1.md](ANDROID_ALPHA1.md). It is not claimed as already passed.
